How it works

Same Mermaid diagrams as the README. Copy any block into a Markdown viewer to re-render it.

1. System overview

Browser
  popup (toggles) --message--> background worker --redirect--> viewer tab
  viewer --uses--> vendor (pdf.js, pdf-lib, qpdf, cmaps)
  viewer --uses--> nevaipdf-ops (merge/split/rotate/watermark)
  viewer <--> IndexedDB (recents + annots)
  viewer + popup <--> chrome.storage.local (prefs)

2. Render pipeline (epoch-guarded)

Open (file/drop/URL/recent)
  -> docIdFor(name+size+hash) -> getDocument -> metadata
  -> baseSizes (page 1 fast, rest chunked) -> buildPages + observer
  -> visible? --yes--> renderPage: canvas + textLayer + linkLayer
  -> highlight + annot overlay -> rendered

3. Privacy: nothing leaves the device

Your PDF --> stays on device (blob: URL) --> renders in page
  --> recents + annots in IndexedDB (local only)
Your PDF - - NEVER - -> Internet

More diagrams (folder map, lifecycle, annotation engine, search engine, edit engine, responsive breakpoints) are in the README and docs/architecture.md.

Under the hood

Engineering notes for contributors: the resilience rules, the storage contract and the performance budget that keep it instant on 1000-page files.

Resilience — every error has a path

error -> type
  stale epoch        -> abort + retryRender once
  render cancelled   -> treat as normal, re-queue
  wrong password     -> unlock modal re-prompts
  CORS on URL fetch  -> hint: download then drag and drop
  file:// blocked    -> hint: enable file URLs permission
  missing vendor     -> fatal banner naming the file
  runtime error      -> global handler -> toast with the real message

Storage and backup flow

open document      -> recents + last page (IndexedDB)
draw or erase mark -> stroke JSON (IndexedDB, pruned to 60 docs)
settings/profile   -> prefs (localStorage)
tools tab actions  -> stopwatch / counters / tracker / todos (localStorage)
Hub -> Backup      => one JSON (format v4)
Hub -> Restore     => re-import (additive, version-tolerant)

Install in 30 seconds

Works on Chrome, Edge, Brave, Opera, Arc — any Chromium browser. Illustrated guide: docs/INSTALLATION.md.

1Clone / Download

git clone https://github.com/Ahmedbakr78/Heros_PDF.git or Download ZIP + unzip.

2Developer mode

Open chrome://extensions → enable Developer mode (top-right).

3Load unpacked

Load unpacked → select Heros_PDF/pdf-studio-extension/ → Pin Heros PDF.

4Local files

Details → enable Allow access to file URLs for file:// auto-open.


git clone https://github.com/Ahmedbakr78/Heros_PDF.git
cd Heros_PDF
# chrome://extensions → Developer mode → Load unpacked → pdf-studio-extension/
# Optional local preview (no install):
cd pdf-studio-extension && python3 -m http.server 8000
# → http://localhost:8000/viewer.html

FAQ

Thirty answers live in docs/FAQ.md. The top 8:

Is it really free?Yes — MIT-licensed, unlimited pages, merges and annotations, no watermark, no account.
Do my PDFs upload anywhere?No. Files stay on your device via blob: URLs. No analytics, no server.
Why won't file:// auto-open work?Enable Allow access to file URLs in chrome://extensions → Heros PDF → Details.
URL open says CORS error?Some hosts block cross-origin fetch. Download the file, then drag and drop it into the viewer.
Are annotations saved?Yes — per-document in IndexedDB, survives reload. Export burns them into the PDF.
Which browsers?Any Chromium (Chrome, Edge, Brave, Opera, Arc). Firefox port is on the roadmap.
Is todo.txt uploaded to the repo?No. It is deleted and git-ignored. Never commit private notes.
Are there emojis in the docs?No. Docs, website and templates are emoji-free by policy, enforced by CI.
